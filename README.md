# magpie-oc2api

在 magpie 里使用你在 Vercel 上的 [oc2api](https://github.com/zhuweiyou/oc2api) 实例。

**只做授权，不改你的项目。** 登录一次 Vercel，插件扫出该账号下所有名字含 `oc2api`
的项目，把它们当作一组出口内部轮询。不部署、不写环境变量、不改任何配置。

> 装了插件还得先自己把 oc2api 部署到 Vercel —— 一个项目一个出口。这个插件只是读它扫到的东西。

## 为什么这样最省事

oc2api 的免费额度按**出口 IP** 计量。你每个 Vercel 项目的出口 IP 都不同，于是
一个 Vercel 账号下的多个 `oc2api-*` 项目就等于多个独立额度池。这个插件把它们合起来用：

```
一个 magpie 账号（你的 Vercel 邮箱）
├── oc2api-us    ┐
├── oc2api-eu    │
├── oc2api-asia  ├─ 每个项目一个独立出口，自动轮询，429 自动切下一个
├── oc2api-eta   │
└── oc2api-au    ┘
```

## 装

```bash
magpie plugin add github:zhuweiyou/magpie-oc2api
```

然后在供应商那一行点 **Sign in with Vercel**。magpie 会打开 Vercel 自己的设备码页面，
浏览器里确认一次即可。再加一个 Vercel 账号就再登录一次，两组互不干扰。

## 密钥怎么来的

不需要你填，也不会覆盖你的：

| 项目情况 | 做法 |
| --- | --- |
| 有 `API_KEY`（你手设的也行） | 通过 Vercel 的 `env pull` 读出**明文**直接用 |
| 完全没有 `API_KEY` | 不带密钥访问（适用于不校验密钥的部署） |

这一点和「读不回密钥」的常见印象不同：项目环境变量列表确实只给密文，
但 `vercel env pull` 那个接口给的是明文，插件用的就是它。所以你手设的那把密钥原样保留，
线上跑的和插件用的是同一个密钥。

读到之后会**写进本地那个文件**（见「数据放在哪」），不再每次去问 Vercel。

## 模型

模型列表只从**一个**项目读，其余项目默认为一致（它们跑的是同一份 oc2api）。
读不到时用内置的那几个，不会让供应商变空。

模型名不带项目前缀，因为项目是内部轮询的，你选的是「模型」不是「某台机器」：

```
big-pickle
beam-free
deepseek-v4.1-flash-free
glm-5.3-flash-free
mimo-v2.6-flash-free
...
```

代理只放行 `big-pickle` 与所有 `*-free`，插件也照这个过滤。

## 轮询与故障切换

每次请求挑一个项目发出去：

- **负载分散**：优先选当时并发最低、累计发送最少的，所以流量平摊到所有出口，
  不会全压在第一个上；
- **429 / 403 / 401 自动切换**：oc2api 的限流是按出口算的，一个出口用完就换下一个，
  最多试 6 个；
- **失败按响应头休息**：oc2api 的 429 会带 `Retry-After`，项目就按它说的时长休息
  （最长一天）；没说明的才退回 10 分钟，其余项目继续跑，到点自动恢复；
- **401 另算**：那是密钥被拒，不是额度用完。会立刻回 Vercel 重读一次密钥并写回；
  重读回来还是同一把的项目休息 1 分钟，不按 10 分钟算。
  重读是**每次请求最多一次**、每个项目最多试一次，不会无限重试；全部休息时直接拒绝，
  连一个请求都不发，并明确说是密钥被拒、让你去 Vercel 改 `API_KEY` 再点 Check in now；
- **切换不影响流式**：oc2api 的 429/403 在响应头阶段就返回，还没开始吐内容，
  所以换项目不会把回答切断。

被拒的项目会从健康列表里暂时移除，账号卡片会写出来，不会静默失败。

重试上限一共三层：每次请求最多试 6 个项目、每个项目最多一次、密钥重读最多一次。
再往上，已经休息的项目不会再被碰，所以密钥错了也不会变成每秒一次的轮询。

## 账号卡片

供应商卡片显示 `5 projects`，每个项目一行：名字、密钥是否存在、已发送多少、
是否正在休息。

项目行上的 **Check in now** 会立刻重扫一次（新建或删除了项目、或在 Vercel 换了密钥后点它）。

每个响应还带一个 `x-magpie-project` 头，说明是哪个项目答的这次请求；
magpie 会把它剥掉，不会送到 agent 那里。

**没有注入任何工具。** 较早的版本注册过 `oc2api_projects` / `oc2api_models` 两个
MCP 工具，现在都去掉了：同样的信息在账号卡片上就能看到，没必要多两个工具占着 agent 的工具表。

## 插件页

侧边栏「插件」里有一页 **oc2api on Vercel**，写清楚它怎么用、两个仓库各是什么，
并列出**这个插件自己的**供应商行（`oc2api`，多登录一个 Vercel 账号就多一行 `oc2api#邮箱`）。

它不列出 Codex、WorkBuddy 之类的其他渠道：`providers:list` 返回的是整个 magpie 的供应商，
而这一页是 oc2api 插件自己的说明页，把别人的账号摆在这里既没用，也容易让人以为它在扫别的东西。
所以只按 `oc2api` / `oc2api#` 过滤。

magpie 的页面沙箱不给它自己的网络，只给它 `package.json` 里声明过的读：

```json
"magpie": {
  "page": { ... },
  "permissions": ["providers:list"]
}
```

没声明的读会被 magpie 当场拒掉，页面上显示 `oc2api on Vercel 没有声明读取 providers:list`。

页面里的仓库地址是**纯文本**，不是链接：沙箱没有 `allow-popups`，`<a target="_blank">`
点不动。地址可以点一下整段选中，复制到浏览器打开。项目清单也不在这一页，在账号卡片上。

## 数据放在哪

一个文件，一个账号一份：

```
<magpie 配置目录>/oc2api-vercel/accounts/<邮箱>.json
```

```json
{
  "email": "you@example.com",
  "readAt": 1793068189000,
  "projects": [
    { "id": "prj_...", "name": "oc2api-us", "origin": "https://oc2api-us.vercel.app", "key": "sk-..." }
  ]
}
```

里面就是账号的项目清单，**每项带着它自己的 `API_KEY`**，所以不用第二个目录、也不用第二个文件。
文件含明文密钥，写入权限 0600（Windows 上这条只是建议，文件仍在你自己账号的配置目录下）。

**项目清单和密钥都只从 Vercel 拉一次，之后一直用本地这个文件。**

启动时先读它立刻可用，然后在后台静默拉一次 Vercel：成功才覆盖，失败就继续用旧的。
只有三种情况会立刻重拉：

| 什么时候 | 拉什么 |
| --- | --- |
| 重新授权 Vercel | 项目和密钥（新账号本地本来也没有） |
| 点 **Check in now** | 项目和密钥 |
| 某个项目回 401（密钥被拒） | 重读密钥并写回——这是唯一能说明你在 Vercel 改了 key 的信号 |

以前是「项目列表每分钟一拉、密钥每 30 分钟一拉」，且**要等读完才发请求**。现在这两个定时器都去掉了：
Vercel 只在你改动它的时候才被问，日常请求完全不碰它。

密钥存盘还顺带治了一个毛病：以前 `env pull` 一旦失败（Vercel 抖动、限流），密钥会被清成空，
5 个项目全部 401 一起休息 10 分钟；现在读不到就用本地已知的那把，请求照发。

登录凭据照常由 magpie 存在 `plugin-auth.json`。

## 边界

- **只读**：这个插件没有部署、创建、删除的能力。项目要新建或改代码，用你的 git 流程。
- **项目名**：匹配规则是「名字里含 `oc2api`」（不区分大小写），`oc2api-us`、
  `my-oc2api-x` 都算，`app` 不算。
- **域名**：用项目的 production 别名（`<项目>.vercel.app`），它在多次部署之间不变。
- **无出口保证**：轮询不等于保证每个出口都还有额度，用完的项目按 `Retry-After` 休息，
  到点后会再试。
- **不查出口 IP**：插件不再为每个项目请求 `/ip`。选项目、判断限流、判断健康都不需要它，
  查一次就是每个项目多一个请求。

## 开发

```bash
npm test
```

37 项测试：项目匹配、轮询分散、失败退出与恢复、密钥随项目一起存取（含 0600 权限）、
模型过滤与命名、配置目录读写（含路径穿越防护）、
页面声明的读与它实际读的一致、插件页只画自己的行、页面不画打不开的链接。

真实账号验证过：扫出 5 个项目、9 个模型、连续 10 次请求严格轮流落在 5 个项目上且全部 200。
冷启动 4.5 秒（打 6 次 Vercel：项目列表 + 5 把密钥）；之后每次请求 0.5 秒，
只在后台刷新一次项目列表，密钥不再重读。
